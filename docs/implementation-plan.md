# 晴序天气实施计划

用户已给出完整需求并授权直接实现；按 Sites 私有站点工作流推进，不再追加设计确认。

1. API 与数据模型：核对 v1 current/daily/hourly、Geo v2 lookup、Ed25519 JWT（iss/sub/kid），集中单位/比例/时间/昼夜处理。先用 node:test 验证坐标、转换、缺失值、范围与认证签名，再实现。保留原始字段供高级视图。
2. 服务端：固定路径白名单，专属 qweatherapi.com Host，JWT 私钥仅 Worker 环境变量；请求校验、超时、限流、去重、有限缓存与明确过期标记；缺配置/401/403/429分开反馈。
3. 地点与持久化：官方目录三级选择，GeoAPI 用 Location ID 确认；全局防抖搜索、键盘选择、浏览器定位与错误处理；城市添加/删除/排序、本地设置、最后城市。
4. 界面：原创晴序品牌，天气渐变与玻璃卡片，大温度；24小时横滑、10天温度区间、11项指标、趋势图；高级页 1–10天/1–240小时及中文字段/原始 JSON。无凭据不展示假天气。
5. 验证与交付：单元/请求集成测试，类型检查、生产构建、本地多端浏览器 QA，Sites 源同步与私有部署；整理真实接口验证限制及配置说明。

重点风险：未知字段不套用旧接口；缺失值不能当0；时间必须按城市时区；过期响应不能覆盖新城市；HTTP响应错误绝不回显上游凭据或原始错误；没有真实凭据无法验证配额、10日和240小时可用性。

选择：使用模板已有 React/Vinext/TypeScript/lucide；SVG绘制数据趋势，无新增包；不接可选空气质量/预警/指数。
