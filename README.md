# 晴序 · 天气与日历

基于 Next.js / React / TypeScript 的天气与日历应用，前端和服务端均可用 Docker Compose 部署到自己的服务器，服务端运行于 Node.js，不依赖 Cloudflare Workers。视觉为原创天空渐变、玻璃卡片与手绘 SVG 天气插画；没有使用苹果专有素材。

## 当前状态

已将两个 Sites 项目的远端最新代码合并：天气界面、城市设置和高级预报保留，新增中国日历、农历节气、官方休班与日期天气查询。GitHub 当前版本已迁移为自托管架构；需要在自己的服务器配置天气凭据。浏览器、镜像和 GitHub 中不包含真实凭据。

默认打开日历，右下角保留一个固定图标按钮：日历页显示太阳图标，天气页显示日历图标，点击前往另一页面，滚动时始终可用；长按日期，在日期旁的悬浮按钮中查看当天天气，返回时保留日期和月份。鼠标右键或键盘 Enter / Shift+F10 同样可打开日期操作。查询支持含今天共 10 日预报与过去 10 日历史再分析；超出范围明确说明，不用当天数据替代。日历今天按北京时间，天气按所选城市日期。年月下方显示选中日期的农历月日，随日期选择更新；不再展示重复的日期详情卡片和日历页连接页脚。

日历页面不请求天气接口，自动定位也延后到进入天气页面；天气概览和常用城市温度只在概览或详细天气页加载，日期天气只查询所选日期。天气不再定时轮询。在天气页面顶部单指下拉或点击顶部刷新按钮，手动获取最新数据；刷新期间保留已显示内容、页面位置与展开状态，失败时保留旧数据并明确标记。页面时钟仅在本地更新时间，不请求天气。

## 部署与运行

完整步骤、环境变量、HTTPS、更新和排查见 [服务器部署文档](docs/deployment.md)。

```sh
cp .env.example .env
# 在服务器编辑 .env，填写和风天气配置
chmod 600 .env
docker compose up -d --build
```

默认访问 `http://服务器IP:8080`。Nginx 接收请求，Node.js 在内部处理页面与所有 API；不需要单独安装 Workers、数据库或 Sites 工具。`/api/health` 验证存活，页面“连接说明 → 重新检查连接”验证真实天气鉴权。

开发环境使用 Node.js >=22.13：

```sh
npm ci
npm run dev -- --hostname 127.0.0.1 --port 4173
npm test
npm run typecheck
npm run build
npm run test:production
```

## 数据协议

- `GET /weather/v1/current/{latitude}/{longitude}`
- `GET /weather/v1/daily/{latitude}/{longitude}?days=1..10`
- `GET /weather/v1/hourly/{latitude}/{longitude}?hours=1..240`
- `GET /v7/historical/weather?location=LocationID&date=yyyyMMdd&lang=zh&unit=m`（过去十天，不含今天）
- `GET /geo/v2/city/lookup?location=名称、LocationID或经度,纬度`

天气路径将纬度、经度保留两位，固定 `localTime=true&lang=zh`。新版值对象按 `{value,unit}` 处理，比例字段 `[0,1]` 转百分比。当前和预报只读取新版字段；历史接口单独适配旧版字符串字段，保留缺失值与数据来源。位置时区来自 GeoAPI；日出日落用于昼夜判断，资料不足时保持中性背景。页面时间均按地点时区显示；正常天气不展示获取时间，过期缓存仍显示时间与异常原因。每日列表的降水百分比是白天/夜间两个时段中较高者，悬浮说明与详情保留两者。

## 功能

- 当前位置、中文/英文模糊搜索、键盘建议列表。
- 官方公开位置 CSV 的3577个地点，34个省级分组，支持内地、港澳台；区县选择后由 GeoAPI 按 ID 在线确认。
- 常用城市添加、删除、上下移动排序、实时温度、当前位置入口、最后位置与偏好本地保存。
- 当前天气、默认24小时和10日预报、9类指标卡片；温度/降水概率/风速趋势图与10日最高最低温曲线。
- 详细天气支持1–10天和1–240小时、图表/列表/中文天气字段；页面保留过期缓存提示与来源声明，不展示原始JSON和接口元信息。
- 日历查天气与预报详情共用弹窗：日期栏支持点选、方向键和空白处左右滑动；日期、温度固定，内容按气温趋势、降水概率、其他指标排列。翻动预报日期复用已加载数据；历史小时温度按真实时区解析，缺失概率不补零。
- 摄氏/华氏、km/h/m/s/mph、自动定位、动画、深浅色偏好；减少动态效果、低核设备和省流模式降级。
- 骨架屏、无数据、网络错误、配置缺失、鉴权、配额、限流与重试状态。

## 安全与性能

私钥只在 Node.js 服务端导入；使用 Ed25519 JWT，包含官方当前规定的 kid、iss、sub、iat、exp，15分钟有效期并预留30秒时钟偏差。请求路径、参数、Host白名单固定，禁重定向，不接受任意URL。

天气缓存为每个 Node.js 进程内最多256条，实时5分钟、预报30分钟；6小时内同地点同范围缓存可在失败时标记为旧数据返回。逐小时刷新额外保留同坐标最近48小时内曾取得的早先预报，供单日详情补齐过去时段，并标注为此前预报；未来预报列表不混入过去小时。首次查询未曾取得的时段无法补齐，进程重启或缓存淘汰后早先预报不保留，历史接口不支持查询今天。浏览器仅当前会话保留最多30条真实天气响应以支持网络失败回退。GeoAPI只合并进行中的请求，不建立响应缓存。官方可下载CSV用于地区选择，不以批量Geo查询建立目录。

同地点请求合并；城市切换取消请求并检查取消状态。服务端每个访问标识每分钟60次的内存限流与错误冷却会在 Node.js 进程重启时重置；这不是跨地区强一致的配额系统。自托管站点默认公开访问，GitHub 仓库为私密。大量访客或多副本场景需另行配置共享限流和额度限制。

## 核心文件

- `Dockerfile`、`compose.yaml`、`deploy/nginx.conf`：服务器构建、启动和入口代理。
- `next.config.ts`、`lib/weather-service.ts`：Node.js 运行方式和服务端环境变量接入。

- `components/calendar-view.tsx`、`components/date-weather.tsx`：月历、键盘交互与指定日期天气。
- `lib/calendar/calendar.mjs`、`public/calendar/data.json`：原日历核心算法与官方数据。
- `lib/date-weather.ts`：城市日期范围、精准匹配与历史响应转换。

- `app/page.tsx`：首页、位置、设置、收藏与高级视图。
- `components/weather-ui.tsx`：图标、卡片、预报列表、中文字段与图表。
- `app/globals.css`：多端布局与天气动态效果。
- `lib/weather.ts`：数据类型、真实单位换算、时区、昼夜与范围计算。
- `lib/qweather-server.ts`：固定路径、安全签名、缓存、限流、错误处理。
- `app/api/{weather,locations,status}/route.ts`：浏览器调用的本站接口。
- `public/locations.json`、`docs/location-source.md`：官方位置目录与溯源。
- `tests/`：合成数据仅用于测试，从未作为网站天气展示。
